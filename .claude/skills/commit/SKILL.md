# Commit

> **重要**: このスキルはユーザーが明示的に `/commit` を呼ぶか「コミットして」と指示した場合のみ実行する。
> 実装完了・ビルド成功のタイミングで自動起動しないこと。

## コミット規約

コミットを作成するときは以下のルールに従うこと。

### メッセージフォーマット
```
prefix: 日本語の説明
```

### prefix一覧
| prefix | 使う場面 |
|--------|---------|
| `feat` | 新機能・新しいページ・新しい要素の追加 |
| `fix` | バグ修正・誤字修正・リンク切れ修正 |
| `docs` | ドキュメント・仕様書・READMEの変更 |
| `style` | 見た目の変更（CSS・レイアウト・色・フォント） |
| `refactor` | 動作を変えないコードの整理・リネーム |
| `content` | ブログ記事・作品ページなどコンテンツの追加・更新 |
| `chore` | 設定ファイル・gitignore・ツール類の変更 |

### 例
```
feat: ヒーローセクションにカワセミのダイブアニメーションを追加
fix: ナビゲーションにContactリンクが抜けていた問題を修正
style: ダークモードのカードホバーエフェクトを調整
docs: 仕様書に演出仕様セクションを追加
content: Aboutページに自己紹介文を追記
chore: faviconをkawasemi_perch.pngからコピーして配置
```

### 小さいコミットにする
- 1コミット1関心事を守る
- 機能追加・スタイル変更・ドキュメント更新が混在していれば複数コミットに分ける
- `git add -A` や `git add .` は使わず、ファイルを明示的にaddする
- 関連ファイルだけをまとめてコミットする

### 仕様書の差分確認・同期

コミット前に、今回の変更内容が以下2ファイルに未反映でないか確認し、反映漏れがあれば先に更新してメインのコミットに含める。

#### `docs/REQUIREMENTS.md`
ユーザー視点の機能要件・演出仕様を記載。以下に該当する変更は更新する：
- ページ構成・レイアウトの変更 → `## 基本構成`
- 演出・ギミック・インタラクションの追加・変更 → `## 演出・ギミック`
- アクセシビリティ等の非機能要件の変更 → `## 非機能要件`

#### `docs/TECH_SPEC.md`
設計・技術仕様を記載。以下に該当する変更は更新する：
- ディレクトリ構成・採用技術の変更 → `## ディレクトリ構成` / `## 技術スタック`
- デザイントークン（カラー・余白等）の追加・変更 → `## デザインシステム（CSS Custom Properties）`
- Works/Blogのフロントマター・型定義の変更 → `## コンテンツコレクション型定義`
- アニメーション・スクロールシーンの設計変更 → `## スクロールシーン設計` / `## アニメーションモジュール設計原則`
- 実装フェーズの進捗・計画変更 → `## 実装フェーズ`

コードを読めば分かる実装詳細は書かず、**設計上の決定・仕様・データモデル** のみを記載する。
仕様書を更新した場合は、対象ファイルと一緒にステージしてコミットに含める（`git add docs/REQUIREMENTS.md docs/TECH_SPEC.md`）。

### 完了後の報告
コミット後は以下の形式で報告する：
```
✅ X件コミットしました
1. feat: ○○を追加（a.html, b.css）
2. fix: △△を修正（c.js）
```
